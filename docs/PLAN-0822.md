## 0. 決策紀錄（Q&A）

| # | 問題 | 決策 |
|---|------|------|
| Q1 | `defaultUrl / defaultHost / defaultPort` 可否簡化為一個？ | **可以**。改為單一設定 `browser.defaultUrl`（字串），預設 `"http://localhost:80"`。改 port 就是改 URL 字串，語意一樣清楚，少兩個設定。 |
| Q2 | 「切換時保留頁面狀態」指什麼狀態？ | 指 webview 內頁面的 **DOM/JS 狀態**：捲動位置、表單輸入、SPA 記憶體狀態（store）、JS timer、WebSocket 連線、console、影片/音訊播放。VS Code 預設在 webview 隱藏數秒後**銷毀並重載**它，狀態全失；`retainContextWhenHidden: true` 則保持 alive（代價是記憶體）。與「iframe 網站本身的資料」無關。 |
| Q3 | 官方內建瀏覽器（僅編輯區）可否沿用部分功能省代碼/性能？ | **不行，也無從省起**。① 官方 integrated browser（1.134+）是 **CDP + Electron debugger + Playwright** 實作（`src/vs/platform/browserView/`），屬內部 platform service；`@types/vscode` 1.134.0 已查證**沒有任何公開 browser API**，擴充無法建立/操控它。② 它是獨立 Chromium session，比我們的 iframe webview **更重**。③ 可沿用的是兩件 OSS 資產：官方 **webview devtools 命令**（見 §7.4）與 **simple-browser** 擴充（MIT，iframe 架構，`extensions/simple-browser`，engines `^1.70.0`）——它是我們架構的直接參考，證明 iframe 方案可行。 |

## 1. 專案概覽

開發一個 VS Code 家族（VS Code / VSCodium / Cursor…）擴充，提供「內建瀏覽器」：

- **單一 Webview View（Panel View Container）**：註冊於**底部面板**（`viewsContainers.panel`），以命令或點擊面板 tab 開啟；使用者可自行拖曳到**側邊副面板**（Secondary Sidebar）——主/副面板是同一個東西，擴充不做兩套。
- **拖曳事實（官方 UX guidelines 已查證）**：編輯區分頁**不能**拖到底部面板或側邊欄；只有**底部面板 ⇄ 側邊副面板**可互相拖曳（`api/ux-guidelines/sidebars.md`："users can drag Views from the Primary Sidebar or the Panel"）。因此瀏覽器以「面板 View」形式存在，**不用編輯區 tab**。
- **圖示模式**：指 VS Code 底部面板 tab 列表的「名稱 / 圖示」兩種顯示，由內建設定 `workbench.panel.showLabels` 控制（`panelPart.ts` 已查證，另有 `workbench.action.panel.toggleShowLabels` 切換）。**這是 VS Code 內建 UI 行為，擴充只需提供正確的 `title` + `iconPath`**，兩種模式自動正確顯示。
- 工具列（codicon 圖示）：網址列（內嵌前往箭頭）、上一頁/下一頁、**重新整理**、Home、**F12 DevTools**、設定按鈕、**「...」選單**（收納：設定、外部瀏覽器、縮放、查找、設備仿真、歷史紀錄、清除存儲）。
- 設定：`browser.defaultUrl`（預設 `http://localhost:80`）。
- 最後上架 **OpenVSX**（測試與實際使用無問題後）。

主要用途：**本機開發預覽**（瀏覽 `localhost:port` 的網站），iframe 內嵌方案即可滿足。

## 2. 研究發現（gh 查證紀錄）

### 2.1 官方 Integrated Browser（VS Code 1.134+）
- 文件：`microsoft/vscode-docs` `docs/debugtest/integrated-browser.md` — 完整功能（網址列、favorites、history、多分頁、session storage、remote proxy、`editor-browser` debug type、獨立視窗、agent 工具）。
- 實作：`microsoft/vscode` `src/vs/platform/browserView/` — **CDP 為底**：
  - `electron-main/browserViewDebugger.ts`：用 **Electron debugger** attach WebContents，`Target.setAutoAttach` 管理 CDP session。
  - `electron-main/browserViewInspector.ts`：元素檢視/評論（Inspector）。
  - `node/playwrightService.ts`：Playwright 驅動。
- 限制：僅編輯區分頁（可 Move into New Window；**無法拖入底部面板/側邊欄**）；**無公開擴充 API**（`@types/vscode` 1.134.0 全文搜尋無 browser API）。
- OSS 原始碼 → VSCodium 1.134 也會有；Cursor（base 較舊）沒有。

### 2.2 官方 webview DevTools（擴充可用的官方實作）
- `src/vs/workbench/contrib/webview/electron-browser/webviewCommands.ts`：命令 **`workbench.action.webview.openDeveloperTools`** — 對「目前聚焦的 webview」（`iframe.webview.ready`）開 DevTools。OSS、家族編輯器通用。**這是我們 F12 的實作基礎**（詳 §7.4）。

### 2.3 simple-browser（可參考的 OSS 實作）
- `extensions/simple-browser`：MIT，iframe + 工具列（back/forward/reload/openExternal），engines `^1.70.0`，`simpleBrowser.show` 命令。架構與我們相同，是「最低可行實作」的基準參考。

### 2.4 圖示模式（面板列表名稱/圖示）
- `src/vs/workbench/browser/parts/panel/panelPart.ts`：`workbench.panel.showLabels`（`false` 時 composite bar 以 `icon` 模式渲染，見第 142 行）+ `workbench.action.panel.toggleShowLabels`。→ 擴充無需自建。

### 2.5 官方工具列 / 設備仿真 / 查找（2026-08-22 gh 查證）
- **DevTools 按鈕圖示**：`browserDevToolsFeature.ts` 使用 `Codicon.developerTools` → 我們 F12 按鈕比照用 codicon `developer-tools`（§7.9）。
- **設備仿真**：`browserViewEmulator.ts` + `browserEditorEmulationFeatures.ts`（EmulationToolbar、device presets、mobile、deviceScaleFactor）— 實作為 Electron `webContents.enableDeviceEmulation` + CDP `Emulation.setDeviceMetricsOverride`，profile 為 `{ width, height, mobile, userAgent, deviceScaleFactor }`（`common/browserView.ts`）。**iframe 擴充無法複製**（無 CDP 控制），只能做 viewport 尺寸模擬（§7.14）。
- **頁面查找**：官方 integrated browser **有** find — `browserEditorFindFeature.ts`：`SimpleFindWidget`（VS Code 內建 UI：Ctrl+F、F3/Shift+F3、大小寫切換、結果計數）+ Electron `webContents.findInPage`（CDP 等級，搜真實渲染頁面）→ **擴充 API 不可用**。VS Code 對 webview 的查找元件實作是 `contentWindow.find(..., searchInFrames=false)`（`webview/pre/index.html` L1287）→ 明確不搜 iframe，跨源也搜不到 → **我們不實作 find**（§7.13）。simple-browser（同為 iframe 架構）也沒有 find。
- **歷史上限**：官方 `workbench.browser.maxHistoryEntries` 預設 200 → 我們比照 `browser.historyLimit` = 200（§7.15）。
- **清除存儲**：官方為 CDP `Storage.clearDataForOrigin` / `Network.clearBrowserCache`；webview 無對等 API → 我們只清擴充自身資料（歷史/lastUrl）（§7.16）。

### 2.6 關閉 / 釋放資源（查證）
- webview view **無程式化關閉 API**（`closeWebviewView` 搜尋 0 命中）；面板 view 無法像 editor tab 一樣被關閉。
- 釋放途徑：① **X 按鈕**清空 iframe（頁面記憶體釋放，工具列/歷史保留）② `browser.retainContextWhenHidden=false` 時 view 隱藏即被 VS Code 銷毀（**完全釋放**，代價：頁面狀態遺失）③ 收合整個面板 `workbench.action.closePanel`（會連 Terminal 等一起收，粗暴，不預設）。
- 對比官方：integrated browser 是 editor tab，可用一般關閉分頁（含 Close All Browser Tabs 命令）。

## 5. 系統架構（簡化為單一 panel）

```
┌────────────────────────────────────────────────────────────┐
│  Extension Host (Node)                                     │
│  src/extension.ts ── activate / 命令 browser.open           │
│        │                                                   │
│        └─ BrowserView.ts ── registerWebviewViewProvider     │
│              │   ├─ 位置：底部面板（viewsContainers.panel）   │
│              │   ├─ 可拖曳：底部面板 ⇄ 側邊副面板（VS Code 內建）│
│              │   └─ 最後網址存 workspaceState（重載還原）      │
│              ├─ config.ts      讀取 browser.defaultUrl      │
│              └─ proxy.ts       (選用) frame 封鎖解除代理     │
└───────────────┬────────────────────────────────────────────┘
                │ postMessage / onDidReceiveMessage
┌───────────────▼────────────────────────────────────────────┐
│  Webview 前端                                               │
│  index.html: CSP + 工具列 + 內容 iframe                      │
│  app.js:     網址列/按鈕事件 → postMessage；接收 configChanged │
│  內容 iframe: src = browser.defaultUrl                      │
└────────────────────────────────────────────────────────────┘
```

- 主/副面板是**同一個 View**，靠使用者拖曳（底部面板 ⇄ 側邊副面板）切換位置，擴充零額外程式碼。
- 圖示模式（名稱/圖示）由 VS Code `workbench.panel.showLabels` 內建處理，擴充提供 container/view 的 `iconPath` 即可。

## 6. 設定設計（`contributes.configuration`）

| 設定 ID | 型別 | 預設值 | 說明 |
|---------|------|--------|------|
| `browser.defaultUrl` | `string` | `"http://localhost:80"` | 預設開啟網址（Home 目標）；port 直接改 URL 字串 |
| `browser.retainContextWhenHidden` | `boolean` | `true` | 切換時保留頁面狀態（見 Q2） |
| `browser.historyLimit` | `number` | `200` | 歷史紀錄上限（同官方 `workbench.browser.maxHistoryEntries`），超出刪最舊 |
| `browser.proxyEnabled` | `boolean` | `false` | 進階：本地代理解除 X-Frame-Options 封鎖（§9） |

即時生效：`workspace.onDidChangeConfiguration` 監聽 `browser.*` → `postMessage('configChanged', config)` → 前端更新 Home 目標（不自動重導向）。

## 7. 關鍵實作細節

### 7.1 單一面板（Panel View Container）與拖曳
`package.json` 貢獻：
```json
{
  "viewsContainers": {
    "panel": [{ "id": "browser-container", "title": "Browser", "icon": "resources/icon.svg" }]
  },
  "views": {
    "browser-container": [{ "id": "browser.view", "name": "Browser", "type": "webview", "icon": "resources/icon.svg" }]
  }
}
```
Extension host：
```ts
vscode.window.registerWebviewViewProvider('browser.view', provider, {
  webviewOptions: { retainContextWhenHidden: cfg.retainContextWhenHidden }
});
```
- 開啟/聚焦：`vscode.commands.executeCommand('workbench.view.extension.browser-container')`（顯示容器並聚焦 view）。
- **拖曳**：底部面板 ⇄ 側邊副面板為 VS Code 內建行為（官方 UX guidelines 確認），擴充零程式碼；**編輯區無法拖入**，屬平台限制，非本擴充缺陷。
- `resolveWebviewView` 時：從 `workspaceState` 還原最後網址 + 注入 HTML（含 CSP）。
- container 與 view 的 `icon` 都要給（圖示模式、拖曳後標頭顯示用）。

### 7.2 圖示模式（名稱/圖示）
- 底部面板 tab 列表：`workbench.panel.showLabels=true`（預設）顯示名稱；`false` 只顯示圖示（icon 模式）— VS Code 內建，無需程式碼。
- 擴充要做的：`panel.title`（"Browser"）與 `panel.iconPath`（SVG）都設好，兩種模式渲染才正確。

### 7.3 重新整理
- 前端直接操作內容 iframe：`iframe.contentWindow.location.reload()`；跨源失敗 fallback `iframe.src = iframe.src`。
- `iframe.onload` 切換 loading 狀態。不經 Extension host，零延遲。

### 7.4 F12 DevTools（官方實作沿用）
官方對「webview」的 devtools 實作就是 `workbench.action.webview.openDeveloperTools`（§2.2，OSS 命令，家族通用）。流程：

1. 前端 F12 按鈕 → `postMessage({ type: 'openDevtools' })`
2. Host：`webviewView.show(true)` 聚焦（若在側邊副面板，先 `workbench.view.extension.browser-container` 顯示容器）→ 小延遲（~100ms）確保聚焦完成
3. `await vscode.commands.executeCommand('workbench.action.webview.openDeveloperTools')`
4. **feature-detect**：啟動時 `vscode.commands.getCommands()` 檢查命令存在；不存在（極舊 fork）→ 提示改用 VS Code 命令列手動執行。

> 注意：官方 integrated browser 的 devtools 是 CDP/Electron debugger 實作（§2.1），擴充無法使用；webview 場景的官方對應物就是上面這條命令。若實測 F12 開錯目標（極少見），fallback：指引使用者從 webview 分頁右鍵選單操作。

### 7.5 外部瀏覽器開啟（「...」選單內）
- 「...」選單項目 → `postMessage({ type: 'openExternal', url })` → `vscode.env.openExternal(vscode.Uri.parse(url))`。

### 7.6 訊息協定（webview ↔ host）

| 方向 | `type` | payload | Host 動作 |
|------|--------|---------|-----------|
| webview → host | `openDevtools` | – | 聚焦 + `workbench.action.webview.openDeveloperTools` |
| webview → host | `openExternal` | `{ url }` | `env.openExternal` |
| webview → host | `openSettings` | – | `workbench.action.openSettings` + `@ext:artin.browser-panel` |
| webview → host | `getConfig` | – | 回傳 `browser.*` 設定 + language + lastUrl |
| webview → host | `navigate` | `{ url }` | 寫入 `workspaceState`（lastUrl + 歷史） |
| webview → host | `historyGet` | – | 回傳歷史列表 |
| webview → host | `historyClear` | – | 清空歷史並回傳空列表 |
| webview → host | `clearStorage` | – | 清歷史 + lastUrl + 通知前端重載 |
| host → webview | `configChanged` | `config` | 更新 Home 目標等 |
| host → webview | `history` | `{ items }` | 歷史列表內容 |

> 縮放、設備仿真為純前端功能（CSS zoom / iframe 尺寸），不走 host 往返。

### 7.7 CSP 與 iframe 瀏覽
```html
<meta http-equiv="Content-Security-Policy"
      content="default-src 'none';
               style-src 'unsafe-inline';
               script-src 'self';
               frame-src http: https:;   <!-- 允許瀏覽任意 http(s) 頁面 -->
               img-src http: https: data:;">
```
不啟用 `enableCommandUris`（避免命令注入面）；按鈕一律走 `postMessage`。

### 7.8 視窗重載還原（workspaceState）
- Webview View 沒有 serializer；視窗重載後 view 會重新 `resolveWebviewView`。
- 前端於每次導航 `postMessage({ type: 'navigate', url })` → host 寫入 `workspaceState`（key: `browser.lastUrl` + 歷史）→ 重載後還原最後網址。

### 7.12 縮放（Ctrl+= / Ctrl+- / Ctrl+0）

- webview 內 `keydown` 監聽（Ctrl 或 Cmd + = / - / 0）。

### 7.13 頁面查找 — 不實作（平台限制，已查證）
- **官方做法**（integrated browser）：`browserEditorFindFeature.ts` 用 `SimpleFindWidget`（Ctrl+F、F3/Shift+F3、大小寫、結果計數）+ Electron `webContents.findInPage`（CDP 等級搜真實頁面）→ **擴充 API 不可用**。
- **VS Code webview 查找元件**：實作是 `contentWindow.find(value, ..., searchInFrames=false)`（`webview/pre/index.html` L1287）→ 明確不搜 iframe；且跨源 frame 依規格也不會被 `window.find` 搜到。
- 結論：webview iframe 架構下**無法**對頁面內容做查找；simple-browser（同架構）也沒有。**決策：不實作 find**，README 註明（需要全文查找的站台請用「在外部瀏覽器開啟」）。

### 7.14 設備仿真 — 限制與實作
- 官方（CDP）：`Emulation.setDeviceMetricsOverride` + `webContents.enableDeviceEmulation`（`browserViewEmulator.ts`），profile 含 `width/height/mobile/userAgent/deviceScaleFactor`。
- **我們（iframe）能做到**：
  - iframe 容器**可拖曳右緣調整寬度**（viewport 寬度 → 響應式媒體查詢/視窗單位會依 iframe 尺寸回應）。
  - 裝置預設：常見手機/平板（如 iPhone、Android 尺寸）+ 自訂寬度輸入。
- **做不到**：DPR（deviceScaleFactor）、touch 事件、userAgent 覆寫 → 文件註明，這些需要 CDP 等級控制。

### 7.15 歷史紀錄
- host 以 `workspaceState`（key `browser.history`）存 `{ url, title?, timestamp }[]`，上限 `browser.historyLimit`（預設 200，同官方 `maxHistoryEntries`），超出刪最舊。
- 選單「歷史紀錄」→ `historyGet` → 前端下拉/面板顯示（依時間倒序，可單筆刪除、全部清除）。
- 歷史記錄以「導航」事件為準（避免 iframe 內 iframe 的 load 污染），去重相鄰重複。

### 7.16 清除存儲
- 「清除存儲」→ `clearStorage`：host 清 `browser.history` + `browser.lastUrl` → 前端重載 iframe。
- **限制**：iframe 站台的 cookie / localStorage 存在 webview partition，VS Code **沒有公開 API** 可清除；真正的「清除瀏覽資料」只有官方 CDP 方案（`Storage.clearDataForOrigin`）能做 → README 註明，本擴充清除的是「擴充自己記的資料」。

### 7.17 關閉 / 釋放資源（X 按鈕）
- 工具列或「...」選單加「X」：前端**移除 iframe src**（頁面 unload → 記憶體釋放），保留工具列與歷史（`workspaceState`），並把 `browser.closed` 旗標寫入 host — **重載/重啟後保持關閉狀態**（不會自動跳回最後網址）；之後按 Home 或「重新開啟」恢復 lastUrl。
- 完全釋放（連 webview 外殼）：`browser.retainContextWhenHidden=false` 時，收合面板/切走即被 VS Code 銷毀，重新顯示時由 `resolveWebviewView` 重建並還原網址 — README 說明此設定即「不用時不佔資源」的開關。
- 無法像 editor tab 一樣真正關閉 view tab（無公開 API，§2.6）；不採用 `workbench.action.closePanel`（會收合整個面板）。

### 7.19 本地代理解除 frame 封鎖（`browser.proxyEnabled`）

**已實作。** 事故與現況見 `docs/PROXY.md`（2026-08-22 閃爍修復）。

**目的**：讓送出 `X-Frame-Options` / CSP `frame-ancestors` 的網站能在 iframe 內顯示（否則白畫面，§9）。這是通用反向代理，不是 Next.js 專用。

**架構**（`src/proxy.ts`，Node http server，僅綁 `127.0.0.1`）：

```
webview iframe ──> http://127.0.0.1:<port>/p/<token>/<scheme>/<host>/<path>
                        │
              proxy.ts（extension host 內）
                        │ http/https.request + pipe（含 POST、WebSocket upgrade）
                        ▼
              剝除 x-frame-options、移除 CSP 的 frame-ancestors
              轉發請求頭（非白名單）；Origin/Referer/Next-Url 改回目標站
              改寫 Location 轉址 header 為 proxy 網址
              根相對路徑走 last-target
              （Set-Cookie 忽略 → 登入不持久）
```

**不要做的事**：注入 `<base>`、改 HTML body。pathname 感知的 SPA 會因此和 canonical redirect 互撞，形成整頁重載迴圈。

**生命週期**：`proxyEnabled` 為 true 才啟動；設定切換經 queue 序列化；deactivate 關閉。
### 7.18 「隱藏」的定義（vs X 關閉）
- **隱藏（hidden）**＝ view 不在 VS Code 版面中：面板 tab 從 Browser 切到 Terminal/Problems/Output、收合底部面板/側邊欄、切到其他 view 容器。**OS 視窗最小化不算**（版面中仍可見）。
- `retainContextWhenHidden=true`：隱藏時 webview 保持 alive → 頁面狀態（捲動/表單/JS/WebSocket）全保留，代價是記憶體。`false`：隱藏即銷毀、重載（狀態遺失）。
- **X 關閉**是獨立動作：一定 unload 釋放記憶體 + 記住網址 + 保持關閉狀態；跨源 iframe 的捲動位置無法讀取，unload 後無法恢復（物理限制）。
- 兩者不衝突、獨立：切到終端 = 隱藏（由設定決定）；X = 明確關閉。

## 9. 限制與對策（iframe 方案）

## 13. 上架 OpenVSX（M5 後執行）

1. **申請 namespace**：到 open-vsx.org 註冊並建立 publisher namespace（例如 `artin`）。
2. **產生 token**：open-vsx.org → Publisher 頁面產生 access token，存環境變數 `OVSX_TOKEN`。
3. **前置要求**（OpenVSX 驗證會擋）：
   - `LICENSE`（MIT）+ package.json `license` 欄位
   - `repository` 欄位（GitHub repo）
   - `README.md`、`CHANGELOG.md`、`description`、`engines.vscode`
4. **發布**：
   ```bash
   npx ovsx publish -p $OVSX_TOKEN   # ovsx 1.1.1，Node ≥ 20
   ```
   與 vsce 共用同一份 .vsix 打包流程（`vsce package` 產出 → ovsx publish）。
5. **發布前檢查**：`vsce ls` 確認 .vscodeignore 生效（體積 < 200KB，無 dev 依賴）。
